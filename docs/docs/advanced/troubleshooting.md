# Troubleshooting

Common issues and solutions for Companion CLI.

> **Early access:** no package-manager release is published. The examples below
> assume `companion` is a shell alias for the source-built jar. See
> [Installation](/docs/installation).

## Installation Issues

### `companion: command not found`

`companion` is not installed as a global binary yet. Create an alias for the jar
you built from source:

```bash
# macOS / Linux
alias companion='java -jar /absolute/path/to/app-cli-0.0.1-SNAPSHOT-exec.jar'
```

```powershell
# Windows PowerShell
function companion { java -jar "C:\absolute\path\to\app-cli-0.0.1-SNAPSHOT-exec.jar" @args }
```

### `Error: Java 21+ required`

```bash
# Check current version
java -version

# Install Java 21+
# macOS: brew install openjdk@21
# Linux: sdk install java 21.0.2-tem
# Windows: scoop install openjdk21
```

### `Error: Docker not found / daemon not running`

```bash
# Start Docker
# macOS/Windows: Start Docker Desktop
# Linux:
sudo systemctl start docker

# Verify
docker system info
```

### Permission denied (Docker)

```bash
# Add user to docker group
sudo usermod -aG docker $USER
# Log out and back in

# Temporary fix
sudo chmod 666 /var/run/docker.sock
```

## Generation Issues

### `companion generate` hangs

```bash
# Check if server is reachable
companion doctor

# Use offline mode
companion generate "..." --name test --offline

# Increase timeout
companion generate "..." --timeout 1200
```

### `Error: Could not connect to server`

```bash
# Check server URL
companion config get serverUrl

# Test connectivity with the development CA (health is public)
curl --cacert certs/ca.crt https://localhost:8443/actuator/health

# Use offline mode
companion generate "..." --name test --offline
```

### `Error: Authentication failed`

```bash
# Check API key
companion config get apiKey

# Set correct key
companion config set apiKey your-correct-key

# Or use env var
export COMPANION_API_KEY=your-key
```

### Generation fails with build errors

```bash
# Check generated project locally
cd generated-project
mvn clean verify

# Common fixes:
# 1. Missing dependencies → Check pom.xml
# 2. Test failures → Check test expectations
# 3. Compile errors → Check generated code syntax
```

### `Access denied` when writing the generated project

The CLI writes to the current directory by default. Use `--project-root` to
choose a writable parent directory:

```bash
companion generate "..." --name test --project-root "$HOME/projects"
```

## Server Issues

### Server won't start

```bash
# Check logs
docker logs orchestrator-server

# Common issues:
# 1. Missing ORCHESTRATOR_API_KEY (must be at least 32 characters)
# 2. Port 8443 in use → Change the mapped port in .env
# 3. PostgreSQL unreachable → Check `docker compose ps`
# 4. TLS files missing → Run ./scripts/dev-up.sh (or .ps1)
```

### Database issues

```bash
# Show container state and logs
docker compose ps
docker compose logs postgres

# Destructive reset of the development database
docker compose down -v
./scripts/dev-up.sh
```

### SSL/TLS errors

The CLI always validates the server certificate and hostname. Use the trust
store generated by `scripts/dev-up`, or point `ssl.trustStore` at the CA that
signed your server certificate:

```bash
companion config set serverUrl https://localhost:8443
# Trust store settings live in ~/.companion/config.yaml
```

`ssl.verifyHostname: false` is ignored with a warning, and there is no
supported option to disable certificate validation. If the server certificate
does not contain the hostname you connect to, regenerate it with the correct
Subject Alternative Name.

### Rate limiting

```bash
# Check rate limit headers
curl -i https://localhost:8443/api/health

# Wait for limit to reset (60s default)
# Or increase limits in application.yml
```

## CLI Issues

### `companion self-update` fails

Self-update needs a published release, and no releases exist yet. Update by
rebuilding from source:

```bash
git pull
mvn -B -ntp -pl app-cli -am package -DskipTests
```

### Colors not showing

```bash
# Enable colors
companion config set noColor false

# Or force
export TERM=xterm-256color
```

### Output truncated

```bash
# Use JSON for full output
companion generate "..." --output-format json | jq .

# Or redirect
companion generate "..." > output.txt
```

## Server Issues

### Health check fails

```bash
# Health is public; trust the development CA
curl --cacert certs/ca.crt https://localhost:8443/actuator/health

# Check server logs
docker compose logs -f orchestrator-server --tail 100
```

### Database connection errors

The server uses PostgreSQL, not H2.

```bash
# Show container state
docker compose ps

# Inspect migrations
docker compose logs orchestrator-server | grep -i flyway

# Inspect tables
docker compose exec postgres psql -U companion -d orchestrator -c '\dt'
```

### Provider errors

```bash
# Provider status requires mTLS plus the server API key
curl --cacert certs/ca.crt \
  --cert-type P12 --cert "certs/client-keystore.p12:$CERT_PASSWORD" \
  -H "X-API-Key: $ORCHESTRATOR_API_KEY" \
  https://localhost:8443/api/health/providers

# Provider settings live on the server, not in the CLI config
docker compose exec orchestrator-server env | grep -E 'NVIDIA|OPENROUTER|OLLAMA'
```

## Getting Help

### Enable Debug Logging

```bash
companion config set logLevel DEBUG
companion generate "..." --verbose
```

### Collect Debug Info

```bash
# System info
companion doctor --output-format json > debug-info.json

# Add to issue
cat debug-info.json
```

### Report Issues

Open an issue in the repository that hosts your clone. Include:

- `companion doctor --output-format json` output
- The full command that failed
- The error message or stack trace
- OS, Java, and Docker versions
- Steps to reproduce

| Code | Meaning |
|------|---------|
| `0` | Success |

| `2` | Invalid usage, missing arguments, or invalid input |
